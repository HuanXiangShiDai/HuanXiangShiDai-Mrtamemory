# 实证记录 002：抽取器接入图

> **关于 L1–L4 的命名（读之前请先看这句）**
>
> 本文的 `L1 / L2 / L3 / L4` 指的是**图上自指环的深度**（δ* = 1/2/3），
> **不是**学界 [Tarski 真层级](https://plato.stanford.edu/entries/tarski-truth/)里的
> L0（对象语言）→ L1（元语言）→ L2（元元语言）。
>
> 两者同名不同义：Tarski 量的是**语言能说多高层的事**，我们量的是**图上的环能绕多深**。
> 你在别处看到 "L1 元语言" 时，不要把它和本文的 "L1 单圈极性 −1" 混在一起。
>
> 与本文更接近的学界概念是图论里的
> [cycle depth](https://www.jair.org/index.php/jair/article/download/13939/26971#11#13#11)
> 和 [Ordinal Folding Index](https://arxivlens.com/paperview/viewpdf/ordinal-folding-index-a-computable-metric-for-self-referential-semantics-4351-425de6ff)。



> 承接 [实证 001](07-实证-元素选取修正.md)。001 里我诚实写了一条：
> 「**过滤 ≠ 修正抽取逻辑**」——那次只是把错误结果挡在召回之外，抽取器照旧粘错词。
> 这一轮把这条补上：**抽取器本身开始读图里的规则。**

---

## 一、要解决的问题

抽取器的停用表是代码常量：

```python
from .lexicon import STOP          # 写死在代码里
_STOP_MULTI = sorted((w for w in STOP if len(w) > 1), ...)
```

后果和"触发条件写死在代码里"一模一样：

- 它不在图里，所以**改不动**
- 改它要发版，不能由系统自己改
- 审计看不见它（它不是规则节点）

---

## 二、做法

### 2.1 新增一条规则：`rule|元素选取`

```
元素选取（这些片段不参与切分，也就不会被抽成元素）：一半天、父亲教
```

词表型，语义是「这些片段在切分时被当作分隔符」——于是它们**不会**成为元素的候选。

### 2.2 抽取器改成"图内口径"

```python
_EXTRA_MULTI: list[str] = []                    # 由规则填进来

def load_stop_from_rules(con) -> int:           # 每次抽之前读一次
    words = rules.element_stop_words(con)
    set_extra_stop(words)

def _split_by_stop(run):
    for w in _EXTRA_MULTI + _STOP_MULTI:        # 规则的词优先（更长、更针对）
        ...
```

`turns.ingest` 入口挂一次 `load_stop_from_rules(con)`。

## 三、验证一：口径真的换了

同一段文本：`父亲教我看星星，我只想了一半天，觉得一半的道理也够用。`

| 口径 | 抽出的元素 |
|---|---|
| 不加载规则（旧：代码常量） | `父亲教`、`星星`、`一半天`、`一半`、`道理`、`够用` |
| 加载规则（新：图内规则） | `星星`、`一半`、`道理`、`够用` |

**区别 = `{父亲教, 一半天}`** —— 两个跨词边界的错误粘合被切掉了。

注意：这不是"过滤结果"。切分阶段就把这两个片段当分隔符了，
所以它们**从未**成为候选元素。这是修正，不是拦截。

## 四、验证二：自指链路能改这条规则

如果规则进了图但只能人工改，那还是半闭环。跑一轮：

### 4.1 输入

```
把「够用」加进停用，元素选取里也不该有它——它是个形容，不是她记得的东西。
```

### 4.2 链路

```
命中触发：rule|触发·加停用（匹配词「加进停用」）
  → stop+ 作用于 rule|元素选取
  → 抽到的词：「够用」（从引号里取）
  → 版本 v1
```

### 4.3 结果

| | 修正前 | 修正后 |
|---|---|---|
| 元素选取停用表 | 一半天、父亲教 | 一半天、**够用**、父亲教 |
| 抽取结果 | 星星、一半、道理、**够用** | 星星、一半、道理 |
| 规则版本 | anchor | **v1** |

**抽取器的行为被自指链路改掉了。**

## 七、仍然没做到的

诚实地说：

1. **切分 ≠ 分词。** `_split_by_stop` 是靠停用词替换 + 单字过滤，不是真正的中文分词。
   「父亲教」被切掉之后，剩下的「父亲」只有 2 字但会被 `_STOP1` 里的「父」影响吗——
   这取决于 STOP 表的内容。**能切掉错的，不等于能切对。**
2. **`lexicon.STOP` 还在。** 两套停用表并存：代码常量（通用虚词）+ 图内规则（针对性修正）。
   完全统一需要把 `STOP` 也搬进图，但那会让每次抽取多查一次库。
3. ~~**规则的读者只有 `turns.ingest` 一条路径**~~ → **已补全员**：`replay.fold_evicted`、
   `wire.ingest`、`wire.ingest_messages`、`write.process_tab` 都挂了 `load_stop_from_rules`。
4. **没有自动发现能力。** 这次是"人指出「够用」不对"，不是系统自己发现的。

## 七点五、接入时暴露的真问题：有两条抽取器

把四个入口挂上之后，实测发现 `够用` 仍然漏抽。查下来是一层更深的原因：

**`extract` 里有两条抽取器**，停用表原本只作用于其中一条。

| 模式 | 实现 | 走不走停用切分 |
|---|---|---|
| `rules` | `rules_elements()` → `_split_by_stop` | ✅ 切分阶段就排除 |
| `llm` | `llm_elements()` → 另走一套 | ❌ **完全不知道停用表** |

而 `turns.ingest` 的调用顺序是：

```python
try:
    _, items = extract.run(raw, "llm")     # ← 先试 llm
except Exception:
    _, items = extract.run(raw, "rules")   # ← 失败才回退
```

所以真实路径**优先走 llm**，而 llm 不认识停用表。规则形同虚设。

### 修法：在出口统一过滤

```python
def run(text, mode):
    ...
    if _EXTRA_MULTI:                        # 图内停用表
        stop = set(_EXTRA_MULTI)
        items = [x for x in items if x.get("surface","") not in stop]
    return ver, items
```

现在两条抽取器都受管辖。实测：

```
rules  → ['星星', '一半', '道理']
llm    → ['看星星', '父亲', '一半', '道理']
turns.ingest 的真实结果 → ['一半', '看星星', '父亲', '道理']
漏抽：无
```

两条抽取器抽出来的词**仍然不同**（这是它们本来的差异：一个按停用词切、一个按模型理解），
但**停用表对两条都生效**——这才是"口径唯一"的含义：不是抽得一样，是**约束一致**。
