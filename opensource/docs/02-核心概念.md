# 02 · 核心概念

一句话：**一张图，四类节点，三条边；元素是唯一中介。**

这一章只讲结构。检索的排序、注入的位置、自指的判据，分别在 03、04 里。

---

## 1. 四张表

库是 SQLite，一个文件。真正装"图"的只有两张表；另外两张是正文和统计的外挂。

| 表 | 主键 | 装什么 | 能不能删改 |
|---|---|---|---|
| `nodes` | `id` | 点：`kind` + `body` + `uniq`（外部身份） | 只增；`uniq` 唯一，重复建点返回同一个 id |
| `edges` | `id` | 边：`src` + `dst` + `rel`；`UNIQUE(src,dst,rel)` | 只增；没有属性列，**没有权重列** |
| `mem_src` | `mem_node` | 记忆正文：`raw` / `first_person` / `when_iso` / `order_key` / `provenance` | 1:1 外挂；正文可按 `src_id` 重写，图的点边不动 |
| `derived_df` | `node_id` | 派生统计：`df` / `total` / `idf` | 可随时整表重算；丢了不影响真相 |

三条要点：

1. **`nodes.uniq` 是身份，不是标签。** 形如 `mem|<src_id>`、`entity|<词>`、`rule|<名>`。
   同一个 `uniq` 永远只对应一个点，所以"再 ingest 一遍同一段话"不会长出第二条记忆——
   它返回的是同一个点。
2. **边没有权重。** `edges` 只有三列，所有权重（idf、覆盖率、中心距离）都是**算出来的**。
   存权重就会漂移，漂移就会有人去改它，改了就没法重算。
3. **正文不在图里。** `nodes.body` 对记忆只放一个短标题（截到 40 字），全文在 `mem_src`。
   图的真相只有点和边；正文换一版不影响结构。

> 库里还有 `meta`（键值）、`session`（会话头指纹）、`extract_run`（抽取切片）三张辅助表。
> 它们不属于"图的真相"，本手册不展开。`scratch` 是第五张表，也是全工程唯一允许
> `DELETE` 的地方，见 03 的"自指"一节。

## 2. 四类节点

`kind` 字段决定这个点是什么。内容节点只有四类：

| 类 | `kind` | 是什么 | `body` 存什么 | 出边 | 入边 |
|---|---|---|---|---|---|
| **mem** 记忆 | `mem` | 她经历过的一件事、或一条设定 | 短标题（≤40 字），全文在 `mem_src` | `has` / `has:lead` → 元素 | `innate`（设定）/ `thought-of` / `supersedes` |
| **element** 元素 | `entity`（情绪词用 `affect`） | 一个词、一个短语，2–6 字 | 词本身 | `refers` → 规则；`seq` → 相邻元素 | `has` / `has:lead`（来自记忆）；`yields`（来自规则）；`mentioned`（来自"用户"） |
| **rule** 规则 | `rule` | 一条行为规矩，或一个旋钮 | `标题：键=值；键=值` 或 `标题：词、词、词` | `yields` → 元素；`current` → 版本 | `refers`（来自元素）；`enacts_up/down`（来自总结） |
| **thought** 思考 | `thought` | 一段思考原文，或一条压好的总结 | 原文（截到 4000 字） | `thought-of` → 记忆；`next` → 思考；`mentions` → 元素 | `next`；`enacts_up/down` |

四条补充：

- **mem 的 `has` 有两档。** `has:lead` 是这条记忆的主元素（"这段话在说谁/说什么"），
  `has` 是其余元素。`df`、骨干、召回都把两者算在内（`E(m)` 的口径）。
- **元素不是一种独立的 `kind`，是一种角色。** 代码里叫 `entity` / `affect`；手册里叫"元素"，
  因为它是"记忆与规则之间的唯一中介"这个结构角色。情绪词（`affect`）有一个特权：
  单字也算元素（"累""笑""哭"），别的词最短两个字。
- **规则是节点，不是配置。** 代码从图里读规则正文，所以"改数据即改行为"。
  规则有版本链，`current` 指针指向生效的那一版；旧版一个字都不删。
- **思考不进召回。** 它不写 `mem_src`、不建 `has` 边，所以在召回、时间轴、头段、
  骨干、回放这些口径里**天然看不见它**。它只有三种边：`thought-of`（想到哪几条记忆）、
  `next`（同会话按顺序串链）、`mentions`（提到哪些元素）。

还有一类不是内容节点的锚点：`kind='center'` 的**中心**。它由 `init` 建出来，
正文取 `huanzao/config.py` 的 `CENTER_BODY`（默认"我"）。中心只有三类边：

```text
center --axis-->    生长素（"一直带着"的几句话，config.AXIOMS，默认空）
center --alias-->   别名（别人怎么叫她，config.ALIASES，默认空）
center --innate-->  设定卡（"我知道的事"，不抽元素，直挂中心）
center --backbone--> 骨干元素（能带住最多记忆的那批元素，可达性用）
```

## 3. 三条边

内容层只有三条边，方向固定：

```text
mem      --has-->      element     这条记忆里有这个元素
element  --refers-->   rule        这个元素指认这条规则
rule     --yields-->   element     这条规则产出这个元素
```

| 边 | 谁建 | 谁读 | 主图量级 |
|---|---|---|---|
| `has` / `has:lead` | 喂语料时（`ingest`） | `df`、骨干、召回、头段"常在我心上的" | 2154 + 376 条 |
| `refers` | `rule_refs.auto_link`（按名字匹配） | `rules_of_element`，权重 **2** | 17 条 |
| `yields` | `rule_yields.seed_yields`（从规则正文抽关键词） | `rules_of_element`，权重 **1**；规则接入图的**主通道** | 124 条边 / 105 个元素 |

关于 `refers` 只有 17 条，不要当成失败：真实图里 1766 个元素，没有几个词的正文和规则名
互为子串。**规则接入图的主通道是 `yields`，不是名字匹配**——规则先产出元素，元素才
指认得回来。这也是为什么 `rules_of_element` 两头都查，并且每条元素最多返回 **2** 条规则
（`CAP=2`）：像"代码""记忆"这种泛词会同时挂在几条规则上，全留就把链变成噪声。

其余边都是脚手架，按用途归类：

| 用途 | 边 |
|---|---|
| 中心 | `axis`、`alias`、`innate`、`backbone` |
| 时间与顺序 | `seq`（元素先后）、`next`（记忆/思考串链）、`when` / `at`（时间节点） |
| 入口 | `topic`（给设定卡加话题键）、`mentioned`（新词挂到"用户"） |
| 自指 | `rewrites` / `unrewrites`（带极性）、`current`（生效指针）、`closes`（回到旧版）、`enacts_up` / `enacts_down`（哪条总结促成了改写） |
| 人格 | `revises_up` / `revises_down`（提案）、`supersedes`（新卡取代旧卡） |
| 思考 | `thought-of`、`mentions` |

## 4. 元素是唯一中介

```
                          ┌──────────────────────────────┐
                          │ 头段（会话头，一次定死）        │
                          │ 我是谁 / 我知道 / 常在我心上    │
                          └──────────────┬───────────────┘
                                         │ innate / axis / alias
                                    ┌────┴─────┐
                                    │  center  │  锚点，不算内容节点
                                    └────┬─────┘
                                         │ backbone（可达性）
                                         ▼
   ┌─────────┐    has / has:lead    ┌───────────┐    refers     ┌──────────┐
   │   mem   │ ───────────────────▶ │  element  │ ────────────▶ │   rule   │
   │  记忆    │                      │   元素     │ ◀──────────── │   规则    │
   └────┬────┘                      └─────▲─────┘    yields     └────┬─────┘
        │                                  │                          │
        │ mem_src                          │ mentions                 │ current
        ▼                                  │                          ▼
   [正文 / 时间 / provenance]        ┌─────┴─────┐              [版本链 v1→v2→v3]
                                     │  thought  │
                                     └───────────┘
```

这张图想说的事只有一句：**四类东西全部通过元素相连，没有谁是孤岛。**

- 记忆靠元素被想起：召回从"这句话里有哪些元素"开始，不是从"哪条记忆的正文像"开始。
- 规则靠元素被指认：`element --refers--> rule`（名字匹配，17 条）和
  `rule --yields--> element`（规则产出关键词，124 条）。没有 `yields`，规则就是图上的孤岛。
- 思考靠元素被挂住：`thought --mentions--> element`，于是"我因为这件事得出的结论"
  能被那个元素反过来调用。
- 人格也走同一条路：新卡 `--supersedes-->` 旧卡、`--innate-->` 中心，而设定卡想被
  元素召回，得先有 `topic` 键。

**元素入口性**（公理 A4）是硬约束：任何召回都必须经过某个元素。没有元素边的点，
（设定卡、思考、规则版本）**不可被元素召回**，只能走显式通道（`innate` / `topic` /
`thought-of`）。这不是实现没做完，是结构如此——所以"某张卡在图上但问不到"时，
第一件事是查它有没有 `topic` 键，而不是去调检索参数。

两个直接推论：

- **新词首轮零命中**（命题 P1）。一个新元素刚建点时 `df=0`，没有任何记忆引用它，
  它对命中分的贡献恒为 0。它要等到第二次被提到、并且已经挂上记忆之后才有用。
  实测：`咖啡` 建点后 `df=0`，紧接着问"我说起咖啡"命中 0 条。
- **孤儿锚不传导**（命题 P2）。链条的第一个元素如果是孤儿（比如"用户"这个锚点本身
  `df=0`），链条的第一跳不产生记忆，命中完全由其余元素决定。

## 5. "只增不改"为什么是纪律，不是限制

**纪律的内容**：点不删、边不删。修正靠**新增**——新版本 + 指针切换、新卡 + `supersedes`、
新边 + 旧边留着。查询时显式跳过被取代的旧东西。

**为什么必须这样**（三个理由，按重要性排）：

1. **它把系统从"可能振荡"变成"必然收敛到下界"。** 只增意味着写入算子是单调的，
   从空图开始喂语料，任意时刻的图都是某个最小不动点的**下近似**——只会越靠越近，
   不会越过（定理 1）。一旦允许删边，单调性没了，轨道可以振荡，不动点可能不存在。
2. **权重不落库，所以能重算。** idf、覆盖率、中心距离全都是 `(V,E)` 的函数。
   如果把权重写进边，它就会和图漂移；漂移之后没人知道该信哪个数。
3. **修正可追溯。** 旧版规则、旧人格卡、旧总结都还在图上，`supersedes` / `current` /
   `rulelog` 记着"谁在什么时候取代了谁"。删掉就只剩一句"现在是这样"，没有来处。

**三个例外，都有明确边界**：

| 例外 | 允许的操作 | 边界 |
|---|---|---|
| `scratch`（临时态） | `DELETE` | 只删"这个 case 的草稿"，思考结束即失效；图里的点边绝不删 |
| `derived_df`（派生层） | 整表重建 | 它是统计缓存，不是真相；随时可从 `edges` 重算 |
| `current` 指针（派生指针） | 原地切 `dst` | 只有这一类边允许改写；每次改必须同时留一个 `rulelog` 节点（谁/为什么/旧→新） |

所以准确的说法是：**点与结构边只增不改；派生指针可切，切则留痕。**

**代价，如实说**：

- 图只会变大。20 条思考写进主图，文件从 3988 KB 涨到 4040 KB；节点 +20、边 +40，
  而记忆数、df 行数、头段指纹**一个没动**——这是"口径隔离"做对了的样子。
- 读的时候要记得过滤。头段必须跳过被 `supersedes` 的旧卡、由新卡原地顶替；
  规则必须读 `current` 指向的版本，不能读锚点；召回必须忽略 `thought`
  （它不写 `mem_src`，天然被忽略）。
- 有些点永远到不了中心。规则版本节点和 `rulelog` 节点不连中心，离心率统计里算"到不了"
  （397 个）——这是有意的：规则靠名字解析，不该靠结构可达。

**它不是"不能改"**：改的是指针和新版本，不是旧数据。使用者感受到的仍然是"规则变了、
人格变了、头段变了"，只是每一次变化都能回退、都能说清来处。

## 6. 最小可用心智模型

把这张图当成一个只有三种动作的系统：

```text
喂料：一段话 ──▶ 1 条 mem ──has──▶ N 个 element ──▶ 重算 derived_df
召回：一句话 ──▶ 命中 element ──▶ 含这些 element 的 mem ──▶ 可达性闸门 ──▶ idf 排序
装配：center/innate/backbone ──▶ 头段（常驻）
      recall 的结果       ──▶ 内容段（每步组装，不进历史）
```

规则和思考是这张图的"旁路"：规则决定召回怎么筛、头段取几条；思考是唯一能改规则的
入口，但只能以类型化的方式改（C2）。下一章按任务讲怎么操作这四条路径。
