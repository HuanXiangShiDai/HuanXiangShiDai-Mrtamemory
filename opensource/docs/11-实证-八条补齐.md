## 二、脉冲扩散：从种子出发抬一圈

```python
activation.pulse_round(con, seeds, hops=2)
```

和 `mg/diffuse.py` 的盲扩散不同：

- `diffuse` 是**找记忆**（要求元素拼齐）
- `pulse_round` 是**抬姿态**（不问拼齐，只问谁被惊动了）

夜间激活要的是后者：让一夜没碰过的元素里，离"最近在想的事"近的那些，先亮一档。

实测：6 个种子 → **扩散 69 个点**。

## 三、四个目标：各有执行器

| 目标 | 做什么 | 返回 |
|---|---|---|
| **总结** | 把还没收口的 scratch case 收成总结（结论顺带落成记忆） | `close_cases` |
| **批判** | 找"结论与前提规则冲突"的地方（结论要收紧、规则却放宽了） | `conflicts` + 例子 |
| **修正** | 把批判结果记成**提案**（不硬改，改要走 C2） | `proposed` |
| **进化** | 读 δ\*、层级、版本数——**只读数，不改任何东西** | `delta_star` / `level` |

`进化` 那条我特意写成"只读数"，因为 δ\* 不是能力分数，是为了让它变大而去改它，就毁了它。

实测一次夜间窗口：

```
窗口 03:00-04:00 | 种子 6 → 扩散 69 点
  [总结] close_cases: 0
  [批判] conflicts: 0
  [修正] proposed: 0
  [进化] δ*=2 / L3 / 规则版本 18
窗口外: 不会跑
```

## 四、定时器：每天 03:00

一个每天 03:00（Asia/Shanghai）的定时任务，内容是 `night run`。
它属于窗口调度，不属于对话——所以发到新会话，不打断你。

**窗口只决定"该不该发车"，不限制跑多久**（`rule|激活窗口` 里 `overflow=允许`）。

## 五、分段协议接进插件

插件 `llm/stream` 钩子从"攒 600 字写一个 thought"改成：


收口时把 `〔自指〕` 段交给 C2 闸门，并在日志里报"模型主动自指"。

## 六、缓冲持久化：跨进程才成立

**这是最容易漏的一条。** 插件每 flush 一次就 spawn 一个 python 进程，
所以进程内的字典活不过一次调用。早先用内存字典的结果是：

```
第1段 landed: []      ← 丢了
第2段 landed: []
第3段 landed: [结论]  ← 只有最后一段能配对
```

改成表 `stream_state(session, turn, step, buf, pending, text, marked, case_id)` 之后：

```
第1段 landed: []
第2段 landed: [条件]        ← 配对成功
第3段 landed: [规则]
第4段 landed: [判别]
第5段 landed: [结论, selfref]

同轮可见（跨进程读）：
  [judge] 她醉后那一面只给特定的人看。
  [conclusion] 那我应该记着，别在别人面前提。

收口：四段完整，scratch 清空
```

## 七、两条新触发成了真通路

之前 `op=manual` 会被 `fire` 跳过，等于纯声明。现在：

| 触发 | 命中后做什么 |
|---|---|
| `触发·夜间脉冲` | 直接调 `night.run_window()`，窗口内就真跑 |
| `触发·主动自指` | 回一句"请在思考里写〔自指〕段"，**不越权替它决定改什么** |

实测：

```
「夜里三点，该自己想想了」→ 命中「夜里三点」→ 夜间通道
「我想改一下常驻取舍」    → 命中「我想改」  → 自指通道
```

**这中间踩了一个坑**：命中要满足三件事——词在文本里、词是图里的元素、元素被该触发 `yields`。
直接建规则节点而不挂元素，规则在图里但永远命不中。

修法：`ensure` 末尾加一步"补挂"——遍历所有触发规则，把 `when` 里还没有 `yields` 边的词补上。
这样规则被改过之后也能追上。

## 八、头段放宽的评估

24 → 32 条，多出来的 8 条是：

```
25. meta 是情感，不是解释
26. 结局：谢幕是她自己要求的
27. 关系：朋友与陪伴，不是恋人
28. 不让你背负罪恶感
29. 用户是乐土消散后第一个走进来的人
30. 记忆：可以忘琐事，不编没发生的事
31. 非官方同人，不冒充官方
32. 乐土消散后，她留在了页边
```

**结论：这 8 条都是"关于她是谁"的硬设定，不是闲聊。**
代价是头段从 748 涨到 874 字（+84 token/轮）。**值得**——这些是行为准则级别的卡
（`不让你背负罪恶感`、`可以忘琐事但不编`），漏掉的代价比 token 高。

## 十二、同步开源包时踩到的三件事

主图与开源包统一时（`tools/sync_opensource.py` 一次复制 27 个模块），暴露了三处**只在同步时才看得见**的问题：

### 12.1 统计口径把已取代的规则算进去了

主图有 8 个早期误建的重复锚点（`rule|放宽` / `trigger|放宽` 等），
按"只增不改"不能删，只标了 `supersedes`。但 `audit` 没排除它们，
规则数被算成 **29**，真正生效只有 **21**。

修：`audit` 里先取 `superseded` 集合再统计。**账错了但审计还"通过"，这比报错更危险。**

### 12.2 同步会覆盖开源包的特有适配

`retrieve.py` 的 30% 泛词硬线：

```python
if r["kind"] != "affect" and share > 0.3:
    continue
```

在 total=560 的主图上永远不触发；但开源包 demo 只有 1–8 条记忆，
**任何元素都占 100%**，于是"init + 喂一句话 + 问"永远召回空。

修：加小图门槛 `total >= 4`。两边一起加（主图加了也不影响）。

> 教训：**主图能跑不等于开源包能跑。** 规模差异会掩盖阈值问题，
> 而同步是单向覆盖，会把别人特意加的适配冲掉。

### 12.3 开源包不该预设具体项目的发现

`DEFAULT_ELEMENT_STOP` 原本预置了 `["一半天", "父亲教"]`——那是主图上的具体错误。
开源包预置它们，会让别人的正常语料被误切。

改成空列表：空时不建规则、`element_stop_words` 返回空集，
抽取行为与没有这条机制时一致。**具体错在哪儿，是每个项目自己的事。**

### 12.4 `cli init` 要建全套规则

只调 `rules.ensure_all` 的话，触发规则 **0 条**、窗口和目标都不存在——
"开箱即用"是假的。现在 `init` 会依次建：配置型规则、触发规则、夜间窗口与四个目标、
思考结论的处理规则。
