# 实证记录 004：分段思考、夜间窗口、第一阶段收尾

> **关于 L1–L4 的命名（读之前请先看这句）**
>
> 本文的 `L1 / L2 / L3 / L4` 指的是**图上自指环的深度**（δ* = 1/2/3），
> **不是**学界 [Tarski 真层级](https://plato.stanford.edu/entries/tarski-truth/)里的
> L0（对象语言）→ L1（元语言）→ L2（元元语言）。
>
> 两者同名不同义：Tarski 量的是**语言能说多高层的事**，我们量的是**图上的环能绕多深**。
> 你在别处看到 "L1 元语言" 时，不要把它和本文的 "L1 单圈极性 −1" 混在一起。
>
> 与本文更接近的学界概念是图论里的
> [cycle depth](https://www.jair.org/index.php/jair/article/download/13939/26971#11#13#11)
> 和 [Ordinal Folding Index](https://arxivlens.com/paperview/viewpdf/ordinal-folding-index-a-computable-metric-for-self-referential-semantics-4351-425de6ff)。



> 这一轮把「思考过程」本身改了：从整段落库变成**按段落地**，于是同一轮思考能调用自己刚得出的结论。
> 同时新增两条自指触发通道、一个夜间激活窗口、四个激活目标。全部写进图，可改。

## 一、分段思考：结论不再等整段想完

### 1.1 之前的问题

`llm/stream` 每攒 600 字写一个 thought 节点，所以**结论要等整段想完才存在**。
实证 003 已经把"事后结论"落成了记忆，但同一轮思考仍然读不到它。

### 1.2 现在：五类段，标记一到就落地

思考里可以带分段标记，`feed()` 识别后按类处理：

```
〔条件〕他在问那天晚上的事
〔规则〕常驻取舍
〔判别〕这件事该留下来，不是可选项
〔结论〕那就留着，不改
〔自指〕规则=常驻取舍 操作=thr↑ 参数=innate:26
```

| 段 | 去处 |
|---|---|
| 条件 | 进 scratch（最终按 `rule\|思考结论` 的 `drop` 决定去留） |
| 规则 | 进 scratch，收口时指向前提规则 |
| 判别 / 结论 | 进 scratch，收口时合成常规记忆 |
| **自指** | **立刻交给 C2 闸门**——只能写"哪条规则、哪个操作、什么参数" |

**没有标记时完全退回旧行为**（整段落库），老流不受影响。

### 1.3 实测

```
第1段 〔条件〕…      已落: []
第2段 〔规则〕…      已落: ['条件']        ← 上一段落地了
第3段 〔判别〕…      已落: ['规则']
第4段 〔结论〕…      已落: ['判别']
第5段 〔自指〕…      已落: ['结论', 'selfref']

同轮可见（中途读）：
  [judge] 这件事该留下来，不是可选项。
  [conclusion] 那就留着，不改。

收口：
  一、在什么条件下：他在问那天晚上的事。
  二、用了什么规则：常驻取舍。            ← 以前这里永远「（没记）」
  三、对什么做了判别：这件事该留下来，不是可选项。
  四、得出什么结论：那就留着，不改。

模型主动自指：ok=True  rule=常驻取舍  op=thr↑  version=v4
```

**四段第一次真的四段都有内容，而且自指是模型在思考中发起的。**

## 六、没完成的（第一阶段收尾，如实列出）

### 6.1 夜间定时器没装

`night.in_window()` / `night.run_window()` 会判断、会跑，但**没有东西在 3:00 叫它**。
需要宿主侧的一个定时器（cron、系统计划任务，或插件 `setInterval` 每 5 分钟问一次）。
这是**本轮最大的缺口**。

### 6.2 脉冲模拟只是骨架

`run_window()` 里对 `activation.pulse_round` 是 `hasattr` 判断——这个函数**还不存在**，
所以"脉冲模拟"目前只有种子选择，没有扩散。

### 6.3 四个目标没有各自的执行逻辑

`总结 / 批判 / 修正 / 进化` 现在是**图里的词**，被 `targets()` 读出来，
但没有任何代码按目标分派不同动作。它们是标签，不是行为。

### 6.4 分段协议只接了 Python 侧

`mg/stream.py` 能正确解析分段，但**插件 `llm/stream` 钩子还在用旧的整段 flush**。
要真正跑起来，得把钩子改成调 `feed()` + `close()`。这是必须做的下一步。

### 6.5 同轮可见只在"进程内"

`pending_conclusions` 从 scratch 表读，跨进程可用；但解析缓冲 `_BUF` 在内存里，
进程重启会丢正在解析的那一段。

### 6.6 抽段仍是启发式

`extract_parts` 靠标志词（所以/因此/其实/看来），没有标志词就退化成"最后一句"。
分段标记是模型自愿写的，模型不写就没有四段。

### 6.7 两个新触发是"声明"，不是"通路"

`rule|触发·主动自指` 和 `rule|触发·夜间脉冲` 在图里，但 `trigger.match` 对它们的
`op=manual` 会直接跳过（`fire` 只认六种原子操作）。它们目前是**说明性规则**，
真正的通路是 `〔自指〕` 段和 `night.run_window()`。

### 6.8 头段放宽的副作用未评估

24→32 条让头段从 748 涨到 874 字（约 +84 token）。每轮都付这个钱，
但"多出的 8 条是否真的有用"没有测过。

## 七、复现

```bash
# 分段思考
python -c "

con = db.connect('out/t.db')

from huanzao import db, night
```
