# 介绍：为什么不是又一个记忆库

> **关于 L1–L4 的命名（读之前请先看这句）**
>
> 本文的 `L1 / L2 / L3 / L4` 指的是**图上自指环的深度**（δ* = 1/2/3），
> **不是**学界 [Tarski 真层级](https://plato.stanford.edu/entries/tarski-truth/)里的
> L0（对象语言）→ L1（元语言）→ L2（元元语言）。
>
> 两者同名不同义：Tarski 量的是**语言能说多高层的事**，我们量的是**图上的环能绕多深**。
> 你在别处看到 "L1 元语言" 时，不要把它和本文的 "L1 单圈极性 −1" 混在一起。
>
> 与本文更接近的学界概念是图论里的
> [cycle depth](https://www.jair.org/index.php/jair/article/download/13939/26971#11#13#11)
> 和 [Ordinal Folding Index](https://arxivlens.com/paperview/viewpdf/ordinal-folding-index-a-computable-metric-for-self-referential-semantics-4351-425de6ff)。



> 这篇写给第一次听到这个项目的人。它回答三个问题：做了什么、跟别人差在哪、边界在哪。

---

## 一、一句话

`huanzao`（幻造工程·元）是一个**把"自指"限制在可审计范围内的元图引擎**。

它吃进一段经历，长成一张只有两种表的图，然后允许系统**改写自己的规则**——
但改写只能"指"，不能"写"；深度可以量，到哪儿停有证明。

## 二、和现有方案的区别

### 2.1 记忆管理类：mem0 / Letta / Zep / Supermemory / Cognee / LangMem

这些是**记忆存取**层：把对话抽成事实、存进向量库或图、按需召回。
做得好的（Zep、Cognee）已经带图和多跳。

**差别不在检索，在"什么可以被改写"。**

它们存的是**事实**——用户的偏好、发生过的事。事实变了就更新事实。
我们存的不只是事实，还有**规则**：召回要几跳、什么词不当种子、什么时候触发改写。
规则在图里、有版本链、有极性账本、能审计、能回滚。

于是多出一件事：**系统可以改自己的规则，而且改得可追溯。**

### 2.2 GraphRAG 类

研究已经证明图检索能省 token（[ACL 2026 报告 19%–53% 的降幅](https://aclanthology.org/2026.gem-main.40/)），
但它们的图是**从语料抽出来就固定**的知识图，优化点在"查得准、喂得少"。

我们的图是**只增不改**的：点不删、边不删，修正靠新增版本。
这不是洁癖——它让任意时刻的图都是最终状态的**下近似**，
于是系统不会在"删了又加"里振荡。代价是图只涨不缩。

### 2.3 自指类：Gödel Agent

[Gödel Agent](https://arxiv.org/html/2410.04444v3) 用 LLM 重写**自身源码**（monkey patching），
是"递归自我改进"最直接的实现。

**这是我们最该对比的一个，也是差异最大的一处。**

| | Gödel Agent | 本项目 |
|---|---|---|
| 改什么 | 程序代码 | 图里的规则节点 |
| 怎么改 | 让 LLM 生成新代码 | 只允许三元组 `(规则, 六种原子操作, 参数)`，**不许生成正文** |
| 能回滚吗 | 靠外部版本控制 | 每条改动是新版本 + `current` 指针，旧版永不删 |
| 能审计吗 | 要读代码 | 独立的一致性检查器 + 极性账本 |
| 改坏了怎么办 | 可能崩溃 | 只增不改，最坏是"多了一个错版本" |

我们用一句约束把这件事变得可承受：**思考只能指，不能写**（记作 C2）。
它没法凭空写出一条新规则，只能对**既有规则**做六种原子操作之一。
实测过：把"放宽"这类同义改写塞进总结，也只会被解释成对既有规则的调参，不产生新正文。

### 2.4 人格漂移类：BRIDGE / Post-Thinking / 角色一致性研究

[BRIDGE（ICML 2026）](https://icml.cc/virtual/2026/poster/62193) 把问题说得很准：
长对话里，agent **说的、内部表示的、存进记忆的**三者会悄悄分开，于是"慢慢出戏"。
[Post-Thinking（FDG）](https://dl.acm.org/doi/10.1145/3815598.3815681) 用滚动反思轨迹来维持一致性。

我们的做法不同：**不追求"不出戏"，而是让"出戏"有记录、有门槛、可回退。**

- 人格卡是一张**可版本化**的卡，不是常量
- 一次思考**改不动**它；同一方向累积到阈值（默认 3）才生效
- 生效 = 新卡取代旧卡，**旧卡永不删**，修订史能查到"是哪几次思考推的"
- 头段里新卡**原地顶替**旧卡的位置（否则二十四条名额一满，修好了也看不见）

## 三、我们真正独有的三件东西

**① 自指深度是可判定的**

不是"我们支持自指"这种口号，而是一组判据：

| 层 | 判据 | 能自证什么 |
|---|---|---|
| L1 | 单圈极性 −1 | 我绕了一圈，符号翻了 |
| L2 | 双圈极性 +1 | 路径闭合，带证书 |
| L3 | δ\*≥2 且存在闭合边 | 对"完成一次周期"再做否定之否定 |
| L4 | δ\*≥3 | 多层边界 |
| L5 | — | **不可达** |

L5 不可达不是工程没做完，是 [Tarski 真不可定义](https://plato.stanford.edu/entries/truth/#TarUndTru) 与
哥德尔第二定理划的线：结构能自证"我走完了"，不能自证"我走对了"。

**② 边界为什么必须是空的，有证明**

自指的闭合条件推出边界算子只能是 $-I$（全局符号翻转）：

$$U(2\pi)=F_0\ \wedge\ U(4\pi)=I\ \Longrightarrow\ F_0=-I$$

$-I$ 是标量，**不携带任何结构信息**。所以"自证边界"在数学上只能是 1 bit 的符号，
不是"一条被冻结的规则"。想让边界记住点什么，数学上做不到——
**记不住，才是边界。**

**③ 规则放进图里，触发条件也放进图里**

这一步让环真正合上。大多数系统把"什么时候改规则"写在代码里，
于是"能改规则"这件事本身不受规则管辖。

我们把触发条件做成图里的节点：

```
rule|触发·放宽   when=多记、多留、放宽；op=thr↑
                   ↓ yields
                元素「多记」「多留」「放宽」
```

文本命中走元素，不查代码常量。于是第 5 条元触发规则出现时——

```
rule|触发·改触发   when=改触发条件、这个触发条件；op=stop+；key=when
```

它删掉了「多记」这个触发词，之后"多记"再也触发不了任何改写。
**系统改变了自己的触发条件。**（实测见 [06-触发规则与闭环](06-触发规则与闭环.md)）

## 四、工程上的四个决定

1. **只有两张表**：`nodes(id,kind,body,uniq)` + `edges(id,src,dst,rel)`。
   没有属性列、没有权重列。**权重永远是算出来的**——存下来就会漂，漂了就没法重算。
2. **零第三方依赖**：只用标准库。一个 4 MB 的 SQLite 文件就是全部状态。
3. **元素是唯一中介**：记忆、规则、思考、人格四类东西全部通过元素相连，没有孤岛。
4. **注入分三种位置**：常驻头段、每步内容段、写进 messages。代价各不同，
   但"写进 messages 必须带标记"这条不妥协——否则注入会被折成"用户说过的话"，
   长出一条假记忆。

## 五、这个项目不适合谁

诚实地说：

- **不适合当通用 RAG 用**。它没有 embedding、没有向量检索，召回靠字面元素命中 + 图可达性。
  要语义检索请用 mem0 / Zep。
- **不适合高频变动的知识库**。只增不改意味着修正靠版本堆积，图会越来越大。
- **不适合要求"人格稳定不变"的场景**。它的设计目标恰恰是让人格**缓慢可塑**。
- **不适合低延迟**。自指链路要收总结、指意图、写版本，不是每步都该跑。

## 六、一句话总结

> 别人的记忆库回答"她记得什么"。
> 这个库多回答两件事：**"她的规则怎么变"**，和**"她知道自己在变，但不知道变得对不对"**。
