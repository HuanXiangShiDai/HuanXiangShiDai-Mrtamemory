# 实证记录 001：修正元素选取

> 一次真实的、自动跑完的自指修正。不是演示脚本，是在工作图上跑的一轮。
> 日期：2026-11-20 · 图规模：560 条记忆 / 1909 个元素 / 7947 条边

---

## 一、实验目的

证明一件事：**系统能自己发现并修正"元素选错了"。**
而且修正过程全在图的管辖范围内——可追溯、可回滚、可审计。

---

## 二、观测点：一个真实的选取错误

「不要」是个虚词，但它被抽取器当成了元素，**而且真的会进入召回**：

```python
>>> hit_elements(con, "他说不要算了，一半也好。")
['不要']
```

`df=1`，在图里，能当召回种子。这就是要修的东西：**一个虚词成了检索入口。**

---

## 三、方法

不写代码、不改抽取器。做法是把「不要」加进 **`rule|操作词`** ——
这条规则的定义就是"命中也不当种子"，它是一张图内的停用表。

修正动作通过**图内的触发规则**完成，由一次思考驱动。

---

## 四、过程（完整链路）

### 4.1 输入：一段思考

```
我想修正一下元素的选取：「不要」这种虚词不该被当成召回种子，
把它加进停用，操作词里也不该有它。
```

### 4.2 落图与收口

| 步骤 | 结果 |
|---|---|
| `thought.record` | 思考进图（`kind='thought'`） |
| `autoself.digest` | 聚成一个 case → `close` → 总结 `sum\|fix-elem\|9\|1`（#3784） |
| scratch | 收口后清空，残留 0 |

### 4.3 指意图（走元素，不查代码）

```
命中触发：rule|触发·加停用（匹配词「加进停用」）
```

触发规则本身是图里的节点，触发词挂成元素：

```
rule|触发·加停用   when=不要再记、加进停用、别记住；op=stop+；key=auto
                     ↓ yields
                  元素「加进停用」
```

### 4.4 执行改写

```
stop+ → 目标规则 rule|操作词 → v2
抽到的停用词：「不要」（从引号里取）
```

### 4.5 落库结果

```
操作词 版本链：
  anchor            （最初）
  anchor ·manual    v1
  anchor ·stop+     v2   ← 本次
```

以及一条**促成边**，这是"谁改的"的账：

```
sum|fix-elem|9|1  --enacts_down-->  rule|操作词|v2
```

## 七、这次实验证明了什么

**① 思考 → 触发规则 → 改配置规则 → 行为改变，四段全通，且全自动。**

没有一行代码被改，没有一个命令行被手动敲。人在链路里只出现一次：提供那段思考。

**② 改动可追溯。**

- 改的是哪个规则：`rule|操作词`
- 从哪版到哪版：v1 → v2
- 谁促成的：`sum|fix-elem|9|1`（那条总结能点开看原文四段）
- 改了什么操作：`stop+`

**③ 系统改变了自己的行为。**

`hit_elements` 的返回值从 `['不要']` 变成 `[]`。这不是统计变化，是**规则变化导致的逻辑分支不同**。

---

## 八、这次实验**没有**证明什么

诚实地说四条：

1. **思考是人给的，不是她自己想的。** 链路自动，但"发现「不要」该被排除"这件事是人先看到的。
2. ~~**抽取器本身没改**~~ → **已在 [实证 002](08-实证-抽取器接入图.md) 补上**：抽取器的停用表搬进了 `rule|元素选取`，切分阶段就排除，且能被触发规则改写。
3. **停用表在规则里，也仍在代码里。** `lexicon.STOP` 是代码常量，`rule|操作词` 是图内表，两套并存。这次动的是后者。
4. **总结的四段只填了第一段。** `digest` 把单条思考按 `condition/judge/conclusion` 轮转填充，
   一条思考只够填 `condition`，其余三段写的是「（没记）」。这是诚实——一条思考确实没有四段结构。
   要四段齐全，得让思考本身分阶段产出。

## 九、附带发现的一个 bug（已修）

`trigger.fire` 里 `stop±` 的抽词逻辑原本是：

```python
w = text.split(trigger["matched"])[-1].strip(" ，。：")[:8]
```

对「把「不要」加进停用，操作词里也不该有它」会抽出**"从操作词里不该有它"**——
取的是触发词**后面**那段，不是要停用的词。

改成：**优先取引号里的词**，退而求其次取触发词**前面**的短片段。

> 这类 bug 只有真跑才会暴露。写测试的时候很难想到"要停用的词在哪一侧"。
