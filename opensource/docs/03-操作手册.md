# 03 · 操作手册

这一章按**任务**组织，不按模块。六件事：喂语料、召回、注入上下文、管规则、做自指、
改人格。每节都是同一个结构：**什么时候用 / 命令 / 参数 / 一个真实输出示例**。

## 0. 两个接口与一个演示库

**CLI（五个命令）**：日常只用这五条，在 `opensource/` 目录下跑。

```bash
python -m huanzao.cli init   --db PATH
python -m huanzao.cli ingest --db PATH --text "..." [--title T]
python -m huanzao.cli recall --db PATH --text "..." [--limit N] [--json]
python -m huanzao.cli remind --db PATH --text "..." [--limit N] [--json]
python -m huanzao.cli status --db PATH [--json]
```

**Python API**：规则版本链、自指、人格没有 CLI 子命令，一律走模块函数。
每个片段都以这两行开头：

```python
from huanzao import db
con = db.connect("out/demo.db")
```

**演示库**：本章所有输出都来自同一个库——`out/demo.db`，由 `examples/story/01..08.md`
八段原创语料 ingest 而成，最后加了一张 canon 卡（第 6 节会建）。它的口径是：

```text
记忆：8
元素：39
边：47
df：39
```

想复现：

```bash
python -m huanzao.cli init --db out/demo.db
# 然后对 examples/story/01..08.md 各跑一次 ingest --text "$(cat 文件)"
```

> Windows PowerShell 里建议先 `$env:PYTHONIOENCODING="utf-8"`，否则中文输出可能乱码。
> 下面所有中文输出都是 UTF-8 原文。

## 1. 喂语料

### 什么时候用

有一条**她经历过的**事要进长期记忆时。一次 `ingest` 只收一件事，不要把一个月的日记
塞成一段。

### 命令

```bash
python -m huanzao.cli ingest --db out/demo.db \
  --text "我们常去城北的旧书店。她翻书很快，我读得很慢。"
```

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--db` | 必填 | 图数据库路径；不存在会报"先跑 init" |
| `--text` | 必填 | 一段话。判重按规范化正文的 sha1，重复写不新建记忆 |
| `--title` | 空 | 记忆标题。不给就取正文前 24 字（图上只存这个短标题） |

### 什么该进图，什么不该

| 该进 | 为什么 | 不该进 | 为什么 |
|---|---|---|---|
| 第一人称、能回溯到具体时刻/场景的一段 | 这是"她经历过"的定义 | 工程对话（改代码、调参、部署） | 她不该记得"改 pipeline" |
| 有具体人、物、地点、情绪的一段 | 抽得出元素，才召回得到 | 第三方转写（`他：` / `user：` / 引号对话稿） | 那是记录，不是她的第一人称记忆 |
| 一个场景一段（几十到几百字） | 一条记忆一个焦点，召回准 | 模型报文、中转消息、重复通知 | 会把"系统说的话"当成她说过的话 |
| 设定类信息（"我是谁"）走 canon 卡 | 设定不抽元素，直挂中心 | 测试数据 | 曾有一条测试报文被当成记忆念出来 |
| 真实的短寒暄（"呀，你来啦"） | 可以进，但接受它不可召回 | 工具名/版本号/连续英文标识 | 抽出来是噪声元素 |

三条必须说清的**实现事实**：

1. **`ingest` 不做工程过滤。** `rule|不入记忆` 那张 46 个词的词表，只有 `replay.py`
   在折块时读（`rules.is_engineering`，命中 ≥2 个词才算工程）。`ingest` 不调它。
   所以"别把工程对话写进记忆"在开源版里**是人工纪律，不是闸门**。
2. **`ingest` 不改写第一人称。** `first_person` 留空，召回时 `render_mem` 退回 `raw`。
   想要自传体，自己先改好再喂。
3. **一条记忆可以一个元素都没有。** 纯寒暄、纯抽象句抽不出 2 字以上的词，就没有
   `has` 边，等于不可召回。实测：某份语料里 14 段短寒暄一个元素都没有。

### 真实输出示例

```text
$ python -m huanzao.cli ingest --db out/demo.db --text "我们常去城北的旧书店。她翻书很快，我读得很慢。"
写进 1 条记忆（mem #47）：我们常去城北的旧书店。她翻书很快，我读得很慢。
元素 5 个，元素边 5 条
```

- `mem #47`：记忆节点的 id。这个数字不是行号，是 `nodes.id`。
- "元素 5 个"是**去重后的元素节点数**；"元素边 5 条"是这次实际新增的 `has` 边数。
- 同一段再喂一次：

```text
这条已经记过（mem #47），原文已更新
元素 5 个，元素边 5 条
```

### 喂完检查：有没有"孤岛记忆"

一条 `mem` 如果没有任何 `has` 边，就永远不会被元素召回。用任意 SQLite 客户端查：

```sql
SELECT m.id, m.body, COUNT(e.id) AS elems
FROM nodes m
LEFT JOIN edges e ON e.src = m.id AND e.rel IN ('has','has:lead')
WHERE m.kind = 'mem'
GROUP BY m.id
HAVING elems = 0;
```

结果非空 = 这些记忆在图上但不可召回。处理办法只有两个：补一段更具体的同场景记忆
让它重新有元素，或者接受它只能走 `innate` / `topic` 通道。

## 2. 召回

### 什么时候用

用户说了一句话，你要知道"她这时候会想起什么"。**它不是全文搜索**：它只认图上的元素，
不认"字面很像"。

### 命令

```bash
python -m huanzao.cli recall --db out/demo.db --text "星星和距离"
python -m huanzao.cli recall --db out/demo.db --text "她愿意等谁" --limit 1
python -m huanzao.cli recall --db out/demo.db --text "旧书店" --json
```

### 召回是怎么走的

```text
一句话
  │
  ├─① 命中元素        retrieve.hit_elements：这句话里出现了哪些图上的元素
  │                    （过滤噪声、机制词、df=0 的孤儿、过泛的词）
  │
  ├─② 可达性闸门      diffuse.pick：从中心 BFS，记忆必须在 max_hops 内，
  │                    且命中元素要覆盖到 min_hit_cov
  │
  ├─③ idf 排序        score = hit_cov × (0.5 + 0.5·hits/elems) × idf ÷ (1+hops)
  │
  └─④ 裁剪            top N（--limit）；每条正文再按注入侧的字数上限截断
```

**① 命中元素**（`retrieve.hit_elements`，上限 12 个）：

- 候选是 `kind` 为 `entity` / `affect` 的节点，正文出现在这句话里；
- 跳过 `NOISE`（寒暄/虚词）和 `META`（记忆、规则、上下文这类机制词）；
- 跳过规则里的**操作词**与**话题词**（"打开""看一下""记忆"指向要做的事，不指向往事）；
- 跳过 `df=0` 的孤儿（没有任何记忆引用它，命中它等于命中空气）；
- **泛词线**：`df/total > 0.30` 不当种子。只在 `total >= 4` 时启用——记忆太少时
  "每条都占 100%"，这条线整体不成立；
- **情绪词豁免**：`affect` 不受 0.30 约束，且允许单字（累、笑、哭）；
- 没有锐词时，退一步交出"最不泛"的一到两个，仍不许整句靠背景词撑；
- 排序：`df` 小的优先 → 近期激活高的优先 → 词长的优先。

**② 可达性闸门**（`diffuse.pick`）：

- 从 `center` 出发 BFS，跳过 `about` / `view` 边（那两条不是路，见 05 第 11 条）；
- 记忆离中心超过 `max_hops`（默认 4）直接不要；
- 命中元素对这句话的覆盖率 `hit_cov` 低于 `min_hit_cov`（默认 0.5）不要；
- 分数按上式重排，取前 N 条。

**③ idf**：`idf = ln(total / max(1, df))`。越稀有的元素越值钱，这是"人名比'今天'重要"
的数学版本。

**④ 裁剪**：`--limit` 默认 3 条。召回只负责"取出正文"，**给模型的字数上限在注入侧**
（下一节）。

### 参数表

| 参数 | 默认 | 位置 | 作用 |
|---|---|---|---|
| 命中元素上限 | 12 | `retrieve.hit_elements(limit=12)` | 一句话最多点亮几个元素 |
| 泛词线 | 0.30 | `retrieve.hit_elements` | `df/total` 超过就不当种子；`total>=4` 才启用 |
| 弱词线 | 0.05 | 同上 | 5%–30% 算"弱"，锐词全无时兜底用 |
| 情绪词豁免 | 开 | 同上 | `affect` 不受 0.30 限制，单字也算 |
| 孤儿过滤 | 开 | 同上 | `df=0` 直接跳过（公理 P2） |
| 最大跳数 | 4 | `rule\|中心校验.max_hops` | 记忆离中心超过 4 跳不要 |
| 命中覆盖率 | 0.5 | `rule\|中心校验.min_hit_cov` | 至少覆盖一半命中元素 |
| 返回条数 | 3 | `--limit` | 最多几条记忆 |
| 单条字数 | 135 | `rule\|提醒措辞.per_mem` | 注入侧每条最多留多少字（见 3.3） |

> **别把 `flow` 的系数当召回参数。** `flow.py` 是另一条"链式"路径，用
> `0.6 / 0.9 / 0.4` 三项加权（单元/邻接/顺序）；开源 CLI 的 `recall` **不走它**。
> 想用链式路径可以直接调 API：
>
> ```python
> from huanzao import db, flow
> con = db.connect("out/demo.db")
> print(flow.flow(con, "她愿意等谁"))
> # {'chain': ['愿意等'], 'missing': [], 'created': [],
> #  'results': [{'mem': 31, 'score': 1.248, 'hits': ['愿意等'], 'ordered': True, ...}], 'note': ''}
> ```

### 真实输出示例

八段语料上，三种结果各来一次：

```text
$ python -m huanzao.cli recall --db out/demo.db --text "她愿意等谁"
召回 1 条（命中元素：愿意等）：
1. 【2026-11-20】我遇见了林。她是我第一个愿意等的人。等一个人和认识一个人不一样，等是要花时间的。

$ python -m huanzao.cli recall --db out/demo.db --text "星星和距离"
召回 2 条（命中元素：星星）：
1. 【2026-11-20】现在我也教别人看星星。我会告诉他们，最近的那颗常常看不见。
2. 【2026-11-20】父亲教我看星星。他说，看得见的那颗不一定是最近的——有些近的，反而被挡住了。

$ python -m huanzao.cli recall --db out/demo.db --text "伞修好了吗"
没有想起什么。
```

第三条为什么空：图上抽出来的元素是"旧伞"，而这句话里只有单字"伞"；"修"也不是元素。
**没有元素命中，就没有召回**——这不是参数没调对，是入口不存在。

`--json` 的形状（一行，方便程序读）：

```json
{"query": "星星和距离", "hits": ["星星"], "results": [{"mem": 64, "title": "现在我也教别人看星星", "text": "……", "when": "2026-11-20", "when_text": "2026-11-20", "view": "", "score": 1.0}]}
```

## 3. 注入上下文

### 什么时候用

你要把"她想起的东西"交给模型，但还没决定放哪。**位置决定代价**，这是本节唯一的重点。

### 三种位置

| | 头段 | 内容段 | messages |
|---|---|---|---|
| 是什么 | `prompt.build_head(con)`：我是谁 / 我知道 / 常在我心上 / 规矩 | `prompt.render_tail(...)`：提醒块 + 用户原话 | 把提醒块拼进这一步的 user 消息 |
| 谁读 | system prompt 的最前面 | system prompt 末尾，或 `systemPrompt.context` 每步组装 | 模型的对话轮 |
| 进历史吗 | 进，但**一次定死** | 不进（每步重算） | 进 |
| 前缀稳定吗 | 稳定；图一变就全变 | 在稳定前缀之后，不破坏前缀 | **每一步都破坏**前缀 |
| 代价 | 每一轮都付同样长度（常驻） | 每步付一次，可裁剪 | 进了历史，之后每轮都要重发 |
| 适合放 | 身份、长期设定、规矩 | 这一轮想起的往事、因果链 | 必须"当面说"的一句提示 |

**头段**（常驻，改动最贵）：

```python
from huanzao import db, prompt
con = db.connect("out/demo.db")
head = prompt.build_head(con)
print(head)
print(len(head), prompt.digest(head), prompt.estimate_tokens(head))
```

真实输出（八段语料，还没有 canon 卡时）：

```text
【我是谁】我。

【常在我心上的】
星星。

【规矩】
· 只说我真记得的事。没经历过的，就直接说不记得、不知道，不许编。
· 记不清的细节，说不记得细节，不要拿想象补上。
· 宁可少说一句，也不要编一句。
---
103 8cba13c9ce3b742c 68
```

- 103 字、指纹 `8cba13c9ce3b742c`、约 68 token。**头段只依赖写死的顺序**：
  `innate` 边的建立顺序，不掺激活值。否则它每轮都变、指纹天天变、缓存前缀全废。
- 头段里任何"会变"的排序都是 bug。这条踩过：曾按激活值排【我知道】，两次构建
  指纹不同。
- 图变了（加卡、改 `常驻取舍`、人格修订）→ 头段变 → 指纹变 → 前缀失效。这是设计
  要付的账，不是意外。

**内容段**（每步组装，不进历史）：

```python
from huanzao import db, prompt
from huanzao.cli import pick_memories

con = db.connect("out/demo.db")
hits, picked = pick_memories(con, "星星和距离", limit=3)
block = prompt.render_tail(con, "星星和距离", picked)
```

真实输出：

```text
【此刻浮上来的】
1. 【内容段·2026-11-20】现在我也教别人看星星。我会告诉他们，最近的那颗常常看不见。
2. 【内容段·2026-11-20】父亲教我看星星。他说，看得见的那颗不一定是最近的——有些近的，反而被挡住了。
（这些是你心里浮上来的，说不说由你；不合适就放过。）

星星和距离
```

`render_tail` 把用户原话附在最后，是因为提醒块最终要和这一句一起进模型。
如果你要把块单独塞进 `system` 末尾，自己把这句去掉。

**messages**（进历史，最贵）：

`agent/pre-step` / 你自己的循环里，把块**前插**到这一步的 user 消息。必须包标记：

```text
〔记忆注入｜脚手架·不是他说的〕
1. 【内容段·2026-11-20】……
〔／记忆注入〕

她愿意等谁
```

这个标记不是装饰：

- 回放折块时 `turns._strip_own` 认它，把注入块切掉，防止"注入被当成她说过的话"再折回记忆
  （公理 A6：脚手架不折）。这是防回音的唯一一道闸。
- 不包标记，注入块会跟着原文进 `mem_src`，下一轮被当成"用户说过的话"召回——闭环就脏了。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `remind --limit` | 图里的 `per_mem`（135 字） | 每条记忆最多留多少字；`--limit 0` = 不截断 |
| `rule\|提醒措辞.title` | `【此刻浮上来的】` | 块标题 |
| `rule\|提醒措辞.footer` | `（这些是你心里浮上来的……）` | 块脚注 |
| `rule\|提醒措辞.per_mem` | 135 | 不传 `--limit` 时每条的字数上限 |
| `rule\|上下文预算.remind_chars` | 220 | **整块**字数预算。主工程由 pipeline 强制；开源 CLI **尚未接**，别以为它会截断 |

逐条截断的真实效果（同一条记忆）：

```text
$ python -m huanzao.cli remind --db out/demo.db --text "星星" --limit 12
【此刻浮上来的】
1. 【内容段·2026-11-20】父亲教我看星星。他说，看
（这些是你心里浮上来的，说不说由你；不合适就放过。）

星星

$ python -m huanzao.cli remind --db out/demo.db --text "星星" --limit 0
【此刻浮上来的】
1. 【内容段·2026-11-20】父亲教我看星星。他说，看得见的那颗不一定是最近的。
（这些是你心里浮上来的，说不说由你；不合适就放过。）

星星
```

### 怎么选位置（一句话）

- 身份和长期设定 → **头段**；它的长度每轮都要付，所以只放"她一直该知道"的东西。
- 这一轮想起的往事 → **内容段**；可以随时裁，不污染历史。
- 必须让她"这一句就照做"的提示 → **messages**；代价是前缀失效，能用内容段就别用。

## 4. 管规则

### 什么时候用

要改召回的闸门、头段取几条、提醒措辞、工程词表时。规则是**图里的节点**，不是配置文件；
改规则 = 写新版本 + 切 `current` 指针，不改代码。

### 命令（Python API）

```python
from huanzao import db, rule_graph

con = db.connect("out/demo.db")

rule_graph.current(con, "上下文预算")          # 当前生效正文
rule_graph.current_version(con, "上下文预算")  # 'v1' / None（还停在锚点）
rule_graph.history(con, "上下文预算")          # [base, v1, v2, ...]
rule_graph.set_rule(con, "上下文预算", "上下文预算：remind_chars=320；tail_tokens=255",
                    "manual", by="lead", why="人工调参")
rule_graph.apply_op(con, "上下文预算", "thr↑", {"key": "remind_chars", "to": "360"},
                    by="system", why="放宽")
rule_graph.revert(con, "上下文预算", "v1", by="lead", why="回退")
rule_graph.cycles(con)                          # 带符号环
rule_graph.audit(con)                           # 外部一致性审计（只读）
```

### 十条默认规则

`init` 建 10 条，`body` 是"标题：内容"的纯文本，代码按前缀/键解析：

| 规则 | body 形状 | 谁读 | 关键键 |
|---|---|---|---|
| 操作词 | 词表 | `retrieve.hit_elements` | 命中也不当种子 |
| 话题词 | 词表 | 同上 | 谈系统时不翻旧账 |
| 中心校验 | `max_hops=4；min_hit_cov=0.5` | `diffuse.pick` | 可达性闸门 |
| 义项裁定 | `margin=0.02` | 主工程 remind | 差到多小才问她 |
| 上下文预算 | `remind_chars=220；tail_tokens=255` | 主工程 / CLI 部分 | 提醒块预算 |
| 时间坐标 | `now_precision=秒` | `times._precision` | 时刻记到多细 |
| 规矩 | `／` 分隔三条 | `prompt.build_head` | 头段最后三条 |
| 提醒措辞 | `title=…；footer=…；per_mem=135` | `prompt.render_tail` | 提醒块措辞 |
| 常驻取舍 | `innate=14；backbone=16` | `prompt.build_head` | 头段取几条 |
| 不入记忆 | 词表（46 个工程词） | `replay` | 折块时挡工程对话 |

### 版本链怎么长

```text
rule|上下文预算            ← 锚点（base，第一条正文）
rule|上下文预算|v1         ← 第 1 个版本
rule|上下文预算|v2         ← 第 2 个版本
锚点 --current--> v2       ← 生效指针（唯一允许原地改写的边）
v1 --rewrites(+1)--> v2    ← 带极性改写边
rulelog|上下文预算|r1      ← 变更留痕：谁/为什么/旧→新
```

规则：**旧版永不删**；`current` 指针切换必须留 `rulelog`；版本名不能再当规则名用。
`rules.ensure_all()` 只补不改（`_put` 默认 `overwrite=False`），所以人工调过的正文不会被
下一次 `init` / `ingest` 打回默认——但**要改正文，别直接 UPDATE `nodes.body`**，
用 `set_rule` / `apply_op`，否则版本链和 `rulelog` 就对不上。

### 原子操作与极性

极性由操作类型唯一决定，不需要人工标：

| 操作 | 极性 | 含义 | 逆操作 |
|---|---|---|---|
| `merge` | +1 | 两义并一，适用集扩大 | `unmerge`（操作集里暂无） |
| `split` | +1 | 一义拆二，适用集不减 | `unsplit`（暂无） |
| `stop+` | -1 | 词进停用表，可用输入减少 | `stop-`（+1） |
| `stop-` | +1 | 词移出停用表 | `stop+`（-1） |
| `thr↑` | +1 | 阈值放宽（数值变大） | `thr↓`（-1） |
| `thr↓` | -1 | 阈值收紧（数值变小） | `thr↑`（+1） |

`merge`/`split` **不是彼此的逆**（两者都扩大适用集），所以它们组成的 2-环极性是 `+1`，
不构成否定环。这就是"L1 逐操作对成立，不是普遍可达"的意思（定理 7'）。

### 真实输出示例（完整一轮）

```python
from huanzao import db, rule_graph
con = db.connect("out/demo.db")

print(rule_graph.history(con, "上下文预算")[0])
# {'ver': 'base', 'body': '上下文预算（提醒块字数、尾段 token）：remind_chars=220；tail_tokens=255',
#  'current': False, 'op': '', 'polarity': None, ...}

print(rule_graph.set_rule(con, "上下文预算",
      "上下文预算（演示）：remind_chars=320；tail_tokens=255",
      "manual", by="lead", why="手册：人工调到 320"))
# {'name': '上下文预算', 'version': 'v1', 'op': 'manual', 'polarity': None, ...}

print(rule_graph.apply_op(con, "上下文预算", "thr↑",
      {"key": "remind_chars", "to": "360"}, by="system", why="手册：再放宽到 360"))
# {'name': '上下文预算', 'op': 'thr↑', 'polarity': 1, 'version': 'v2',
#  'new': '上下文预算（演示）：remind_chars=360；tail_tokens=255'}

print(rule_graph.revert(con, "上下文预算", "v1", by="lead", why="手册：回退"))
# {'name': '上下文预算', 'from': 'v2', 'to': 'v1', 'polarity': -1,
#  'body': '上下文预算（演示）：remind_chars=320；tail_tokens=255'}
```

环检测（这就是 L1 的单圈）：

```python
rule_graph.cycles(con)
# [{'规则': ['上下文预算', '上下文预算'], '极性': -1, '长度': 2,
#   '节点': ['rule|上下文预算|v1', 'rule|上下文预算|v2'],
#   '边': [{'src': '...v1', 'dst': '...v2', 'rel': 'rewrites', '极性': 1},
#          {'src': '...v2', 'dst': '...v1', 'rel': 'unrewrites', '极性': -1}],
#   '自指': True}]
```

外部审计（**不经过写入路径**，自己的 SQL、自己的解析）：

```python
rule_graph.audit(con)
# {'ok': True, 'rules': 10, 'versions': 2, 'current_edges': 1, 'problems': []}
```

四项检查：①同名多 `current` 指针 ②`current` 指向不存在的节点 ③`body` 解析失败
④阈值越界。自指不能保证一致性，所以必须有一把站在外面的尺子（边界 3）。

### 参数与坑

| 坑 | 表现 | 怎么办 |
|---|---|---|
| 数值参数传了 int | `apply_op` 报 `TypeError`（`_as_number` 只吃字符串） | 传字符串：`{"to": "360"}`；`rule_c2.typed_write` 会替你转 |
| `by` 留空 | `audit_c2` 把 `by=""` 记成 `"-"`，判成自由文本写入 | 练习时给 `by="system"` / `"lead"` / `"tester"` |
| 直接改 `nodes.body` | 版本链、`rulelog`、审计全对不上 | 走 `set_rule` / `apply_op` |
| 改完规则想"恢复默认" | `ensure_all` 只补不改，不会覆盖 | 写新版本或 `revert` 到 base；别指望重置 |

## 5. 做自指

### 什么时候用

想让**思考**改规则，而不是人手改；并且要留下"哪条总结促成了哪次改写"的证据（L3 的入口）。

### 命令：临时态 → 总结

```python
from huanzao import db, scratch

con = db.connect("out/demo.db")
cid = scratch.open_case(con, "demo", 1, 0)      # 会话、轮、步 → 'demo|1|0'

scratch.note(con, cid, "condition", "用户问到「伞」")
scratch.note(con, cid, "rule", "常驻取舍")
scratch.note(con, cid, "judge", "这条记忆该不该常驻")
scratch.note(con, cid, "conclusion", "常驻名额可以多给两格")

s = scratch.close_case(con, cid)
print(s["uniq"], s["scratch_deleted"])
```

### 参数

| 参数 | 约束 | 说明 |
|---|---|---|
| `kind` | `condition` / `rule` / `judge` / `conclusion` | 四类 note，对应总结四段 |
| note 正文 | ≤2000 字 | 临时态，不追求完整（`BODY_CAP`） |
| 总结每段 | ≤240 字 | 总结是压缩，不是搬运（`SECTION_CAP`） |
| 规则名 | ≤40 字，只留名字 | 正文已在规则节点里，抄进总结就是二次落库 |
| `close_case` | 幂等 | 同一 case 重复 close 不会长第二条总结 |

### 真实输出示例

```text
## PENDING
["demo|1|0"]

## SUMMARY-BODY
自指思考总结（会话 demo 第 1 轮第 0 步）
一、在什么条件下：用户问到「伞」
二、用了什么规则：常驻取舍
三、对什么做了判别：这条记忆该不该常驻
四、得出什么结论：常驻名额可以多给两格

## SCRATCH-DELETED
4

## PENDING-AFTER
[]
```

四件事同时发生：

1. 总结写成 `kind='thought'` 的点，`uniq = sum|demo|1|0`；
2. 连三类边：`sum --thought-of--> mem`（想到的记忆）、`sum --refers--> rule`（用到的规则）、
   `sum --mentions--> element`（提到的元素）——总结不能是孤岛；
3. `scratch` 里这个 case 的 4 行全部删除（**全工程唯一允许 DELETE 的地方**）；
4. 记忆数不变：`status` 的 `记忆` 不动。

### 命令：C2 类型化写入

```python
from huanzao import rule_c2

rule_c2.typed_write(con, s["uniq"], "常驻取舍", "thr↑", {"key": "innate", "to": 26},
                    by="thought", why="手册 A1")

rule_c2.depth(con)      # {'δ*': 2, 'per_rule': {...}, 'L': 'L3'}
rule_c2.audit_c2(con)   # {'ok': True, 'free_text_writes': [], ...}
```

### 参数（C2 的闸门）

| 闸 | 规则 | 真实拒绝信息 |
|---|---|---|
| 操作 | 六种原子操作之一 | `RuleError: 不认识的原子操作 '乱来'；……['merge', 'split', 'stop+', 'stop-', 'thr↑', 'thr↓']` |
| 参数键 | 只能是 `key/to/a/b/w/into` | `C2Error: 参数键 'body' 不在白名单 ['a', 'b', 'into', 'key', 'to', 'w'] 里` |
| 参数值 | ≤40 字；不含换行/分号/冒号 | `C2Error: 参数 to 的值像正文（含换行/分号/冒号），C2 拒绝` |
| 新正文 | 只由 `rule_graph.apply_op` 从旧正文推导 | 思考拿不到"写正文"的句柄（结构上做不到） |

### 真实输出示例：L3 的完整两圈

起点：把 `常驻取舍` 人工设成 `innate=24`（`set_rule(..., "manual")`）。

```text
## C2-A1
{"name": "常驻取舍", "op": "thr↑", "polarity": 1, "version": "v2",
 "enacts": "enacts_up", "closes": null}

## C2-A2
{"name": "常驻取舍", "op": "thr↓", "polarity": -1, "version": "v3",
 "enacts": "enacts_down", "closes": "v1"}

## DEPTH
{"δ*": 2, "per_rule": {"常驻取舍": 2}, "L": "L3"}

## AUDIT-C2
{"ok": true, "free_text_writes": [], "note": "非人工写入必须走 typed_write，出来必带 enacts 边"}
```

- 第一次：`innate 24 → 26`（`thr↑`，`enacts_up`）→ `v2`；
- 第二次：`innate 26 → 24`（`thr↓`，`enacts_down`）→ `v3`，`closes v1`；
- 数值回到原点，版本链多两层 → `δ* = 2` → **L3**。
- **头段指纹不变**：因为 `innate` 回到 24，头段内容等价。这正是"合题"的样子——
  参数回到原点，结构留下两圈。

L2 与 L4 的判据、`F0` 为什么只能是 `-I`、C1/C2 谁承重，见
[04-自指与人格](04-自指与人格.md)。这里只记住一句：**C2 不是"限制她改规则"，是取消
"写一段新正文"这个动作**——她只能从旧正文推导，不能自撰。

## 6. 改人格

### 什么时候用

同一方向的结论反复出现，到了阈值才改。**单次思考不改人格**——一次情绪波动改不动她，
这是"长期化"的定义。

### 先建一张 canon 卡（人格修订的对象）

`ingest` 写的是"经历"，不是"设定"。设定要手工建：一条 `mem` + `mem_src` 里
`when_iso='canon'`，再挂到中心的 `innate`。

```python
from huanzao import db, prompt
con = db.connect("out/demo.db")

card = db.node(con, "mem", "核心：怕被遗忘", uniq="canon|demo|core")
con.execute(
    "INSERT OR REPLACE INTO mem_src(mem_node, src_id, raw, first_person, fp_ver, "
    "when_iso, order_key, provenance) VALUES(?,?,?,?,?,?,?,?)",
    (card, "canon|demo|core", "核心：怕被遗忘。做决定前先想会不会被忘记。",
     "核心：怕被遗忘。做决定前先想会不会被忘记。", "canon", "canon",
     "0:000:0000000000:00000000:0000000000:000900", "canon:核心"))
center = con.execute("SELECT id FROM nodes WHERE kind='center' LIMIT 1").fetchone()["id"]
db.edge(con, center, card, "innate")
con.commit()

print(len(prompt.build_head(con)))   # 120
```

- `when_iso='canon'` 是"设定"的记号；`order_key` 的段号 `0` = 先天设定。
- `provenance='canon:核心'` 里的"核心"是门类，召回渲染成 `【头段·我知道｜核心】`。
- 不挂 `innate` 它进不了头段；想让它能被"问某个词"翻出来，还要 `topic` 键（见 05 第 5 条）。

### 命令：提案 → 阈值 → 生效

```python
from huanzao import persona, scratch

for i in (3, 4, 5):
    c = scratch.open_case(con, "demo", i, 0)
    scratch.note(con, c, "conclusion", f"第 {i-2} 次觉得「怕被遗忘」该写得更清楚")
    scratch.close_case(con, c)
    persona.propose(con, c, "canon|demo|core", +1, why="手册：同向提案")
    print(persona.tally(con, "canon|demo|core"))

ap = persona.apply(con, "canon|demo|core",
                   "核心：怕被遗忘，但不用它绑人。先记住谁在我面前放松过，再谈爱人类。",
                   threshold=3, by="system")
print(ap)
```

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `direction` | 必填 | `+1`/`-1`（也认"加强"/"削弱"）；写进 `revises_up` / `revises_down` |
| `threshold` | 3 | 净票 `up - down` 到 3 且 `net > 0` 才生效 |
| `canon_uniq` | 必填 | 被修订的卡；第一次修订产生 `canon|demo|core|r1` |
| `supersedes` | 自动 | 新卡 → 旧卡；旧卡永不删 |
| `innate` | 自动 | 新卡挂中心，**原地顶替**旧卡的位置 |

### 真实输出示例

```text
## TALLY-1
{"canon": "canon|demo|core", "up": 1, "down": 0, "net": 1}
## TALLY-2
{"canon": "canon|demo|core", "up": 2, "down": 0, "net": 2}
## TALLY-3
{"canon": "canon|demo|core", "up": 3, "down": 0, "net": 3}

## APPLY
{"applied": true, "tally": {... "net": 3}, "new": "canon|demo|core|r1",
 "old": "canon|demo|core", "by": "system",
 "body": "核心：怕被遗忘，但不用它绑人。先记住谁在我面前放松过，再谈爱人类。"}

## HEAD-CHARS
{"before": 120, "after": 146}

## REVISIONS
[{"new": "canon|demo|core|r1", "now": "核心：怕被遗忘，但不用它绑人。……",
  "was": "核心：怕被遗忘"}]

## HEAD-LINE
{"index": 3, "text": "· 核心：怕被遗忘，但不用它绑人。先记住谁在我面前放松过，再谈爱人类。"}
```

**位置继承**是这一步的关键：新卡的 `innate` 边本来排在最后，名额一满（默认 14，
主图实测调到 24）它永远进不了头段。`build_head` 的规则是"被 `supersedes` 的旧卡不出现，
由新卡原地顶替"，
所以新卡出现在旧卡原来的第 3 行（0 起算），头段从 120 字变成 146 字，指纹随之改变。

代价：**人格一变，缓存前缀就废**。这是有意接受的价格——"她变了"必须看得见，
否则改人格等于没改。

### 改完检查

```python
persona.revisions(con)      # 谁取代了谁
prompt.build_head(con)      # 新卡在不在头段、在第几行
prompt.digest(...)          # 指纹变了没有（变了就说明真的改了）
```

## 7. 速查：什么任务走哪个接口

| 任务 | 接口 | 入口 |
|---|---|---|
| 喂一段经历 | CLI | `ingest --db --text` |
| 问"她会想起什么" | CLI | `recall --db --text` |
| 生成可注入的提醒块 | CLI | `remind --db --text [--limit]` |
| 看口径 | CLI | `status --db` |
| 建设定卡 / 改中心 | Python | `db.node` + `mem_src` + `innate` |
| 改规则、回退、看版本链 | Python | `rule_graph.set_rule/apply_op/revert/history` |
| 带符号环检测 | Python | `rule_graph.cycles` |
| 外部一致性审计 | Python | `rule_graph.audit` |
| 思考临时态 → 总结 | Python | `scratch.open_case/note/close_case` |
| 类型化改规则（C2） | Python | `rule_c2.typed_write` |
| 自指深度 / C2 审计 | Python | `rule_c2.depth/audit_c2` |
| 人格提案 / 生效 | Python | `persona.propose/tally/apply` |

规则、自指、人格之所以不给 CLI，是有意的：**它们改的是结构，不是日常操作**。
把它们做成随手一条命令，等于把"只增不改 + 阈值 + 审计"那套纪律稀释掉。
