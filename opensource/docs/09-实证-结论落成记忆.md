# 实证记录 003：思考的结论落成记忆

> 承接 [实证 002](08-实证-抽取器接入图.md)。这一轮补的是**思考的产出**——
> 之前"四段总结"只是格式，第二、四段永远是「（没记）」。

---

## 一、问题：四段总结是格式，不是机制

实测一次真实的 `digest`，输出是这样：

```
一、在什么条件下：我在想某个角色的往事。她端着酒杯…（整段思考）
二、用了什么规则：（没记）
三、对什么做了判别：我在想某个角色的往事…（又是同一段）
四、得出什么结论：（没记）
```

原因：`digest` 把同一条思考按 `condition/judge/conclusion` **轮转填充**。
一条思考只够填第一段，第三段是重复，第二、四段永远空。

后果很硬：**"思考得出过什么结论"这件事，在图上根本不存在。**

---

## 二、改法：四段各有归宿

| 段 | 去处 |
|---|---|
| 一、条件 | **丢掉**（只对当时那一刻有意义） |
| 二、规则 | 抽规则名 → `refers` 指向前提规则 |
| 三、判别 | 与结论合成**一条常规记忆** |
| 四、结论 | 同上 |

原文不动：`thought` 节点照旧保留。

### 2.1 从自由文本抽三段（不改思考协议）

模型仍然自由输出，不从格式上要求它分段。所以在**文本侧**用启发式抽：

- **规则**：直接匹配图里已有的规则名（配置型 + 触发型，取短名）
- **结论**：含结论标志词的句子（`所以/因此/可见/结论是/我决定…`）；没有就取最后一句
- **判别**：含判别标志词的句子（`其实/看来/说明/并不是/而是…`）；没有就取结论之外最长的一句

### 2.2 三道门槛：宁可不写，也不写空话

| 门槛 | 拒绝条件 |
|---|---|
| 长度 | 结论 < `min_len`（默认 8 字）——「今天没什么特别的」不是结论 |
| 元素 | 判别+结论里一个图内元素都没有——没有元素就召不回来，写进去是死数据 |
| 区分 | 判别与结论是同一句——等于没判别 |

### 2.3 结论怎么写才"像一条常规记忆"

要有 `mem_src`、要有 `has` 边、要进 `derived_df`。这里踩了两个坑：

**坑一：元素只挂到 1 个。** 结论里的词大多是组合词（「被记住」「数清楚」），
`_elements_in` 命中不了几个。改成用抽取器切一次，图里没有的**建点**——
结论记忆得先有入口。

**坑二：新建元素后 `derived_df` 没重算。** 结果这些元素在 df 表里没有行，
`hit_elements` 把它们当孤儿跳过，结论记忆永远召不回来。

## 三、实测

输入：

```
我在想常驻名额这件事。其实她真正需要的是被记住，而不是被数清楚。
所以常驻取舍应该放宽一点，让更多东西留下来。
```

产出：

```
结论记忆 #3794
  判别：其实她真正需要的是被记住，而不是被数清楚。
  结论：所以常驻取舍应该放宽一点，让更多东西留下来。

  → 指向前提规则：rule|常驻取舍|v3、rule|放宽
  → 挂住元素(8)：放宽、真正需要、判别、记住、更多东西留下、常驻取舍、数清楚、结论

召回：
  「她真正需要什么」→ 命中「真正需要」 ✓
  「被记住」        → 命中「记住」     ✓

耗时：digest + 落记忆 108 ms
```

**结论现在是可召回的、"凭什么这么想"是可反查的。**

## 四、处理方式本身也进图

```
rule|思考结论
  思考结论（思考怎么落成记忆）：keep=judge,conclusion；drop=condition；
                              rules=rules→refers；mem=常规记忆；min_len=8
```

它和元素选取、触发条件一样，是**图里的规则**，因此：

- 有版本链
- 能被触发规则 / C2 类型化写入改写
- 能被独立审计

实测改它：`min_len` 8 → 12 之后，「结论是留下就好」（10 字）立刻被拒：

```
结论太短（< 12 字）
```

**"思考怎么落成记忆"这件事，现在也是可自指的。**

## 五、向上输出的放宽

| 参数 | 原 | 现 | 理由 |
|---|---|---|---|
| 注入条数 | 3 | **6** | 结论记忆密度高于原文，值得多带 |
| 单条截断 | 400 字 | **200 字** | 结论比细节有用 |

一次上下文量级（实测）：

```
头段 498 token + 提醒 520 字 + 因果 254 字 ≈ 1014 token
放宽到 6 条后：+ 约 600–800 token，总量 ≈ 1800 token
```

## 六、仍然没做到的

1. **条件段被丢掉了。** 这是按你的决定做的，但它意味着"当时的处境"不可回溯。
   想留的话，改 `rule|思考结论` 的 `keep` 就行——规则在图里。
2. **抽段靠标志词，不是理解。** 「所以」后面不一定真是结论。
   没有标志词时退化成"最后一句"，可能抽错。
3. **思考过程仍然不同步。** 这一轮改的是**事后**：思考结束后才落结论。
   要让"同一轮思考调用自己的结论"，还得改思考协议（分段输出 + 分段落库），
   这次按你的要求**没动**。
4. **`min_len` 是拍出来的。** 8 字没有依据，只是"能挡住流水账"的经验值。

## 七、复现

```bash
# 1. 处理规则进图
python -c "from huanzao import conclusion, db; conclusion.ensure_rule(db.connect('out/t.db'))"

# 2. 造一段思考并收口
python -c "
from huanzao import db, thought, autoself
con = db.connect('out/t.db')
t = '我在想常驻名额。其实她真正需要的是被记住，而不是被数清楚。所以常驻取舍该放宽一点。'
thought.record(con, {'session':'demo','turn':1,'step':1,'seq':0,'text':t}, bump=False)
autoself.digest(con, 'demo', 1, 1)
"

# 3. 看结论记忆
python -c "
from huanzao import db
con = db.connect('out/t.db')
for r in con.execute(\"SELECT n.body FROM nodes n JOIN mem_src s ON s.mem_node=n.id WHERE s.provenance='thought-conclusion'\"):
    print(r['body'])
"

# 4. 改门槛（自指）
python -m huanzao.cli c2 write --summary sum|demo|1|1 --rule 思考结论 --op thr↑ --key min_len --to 12
```
