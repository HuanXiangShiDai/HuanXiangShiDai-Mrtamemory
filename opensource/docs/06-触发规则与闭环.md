# 触发规则与闭环：让"什么时候改"也进图

> **关于 L1–L4 的命名（读之前请先看这句）**
>
> 本文的 `L1 / L2 / L3 / L4` 指的是**图上自指环的深度**（δ* = 1/2/3），
> **不是**学界 [Tarski 真层级](https://plato.stanford.edu/entries/tarski-truth/)里的
> L0（对象语言）→ L1（元语言）→ L2（元元语言）。
>
> 两者同名不同义：Tarski 量的是**语言能说多高层的事**，我们量的是**图上的环能绕多深**。
> 你在别处看到 "L1 元语言" 时，不要把它和本文的 "L1 单圈极性 −1" 混在一起。
>
> 与本文更接近的学界概念是图论里的
> [cycle depth](https://www.jair.org/index.php/jair/article/download/13939/26971#11#13#11)
> 和 [Ordinal Folding Index](https://arxivlens.com/paperview/viewpdf/ordinal-folding-index-a-computable-metric-for-self-referential-semantics-4351-425de6ff)。



> 这一篇讲这个库最特别的一处：**触发条件本身也是图里的节点**，所以它也能被改。
> 环在这里合上。

---

## 一、起点：一个藏在代码里的漏洞

最早的做法很自然——把触发条件写成代码常量：

```python
OP_WORDS = [("放宽", "thr↑"), ("收紧", "thr↓"), ("加进停用", "stop+"), ...]
```

系统能改规则，但**"什么时候改规则"由代码说了算**。

这个漏洞很隐蔽：你以为系统是自指的，其实自指只到一半——
**规则可改，但改规则的条件不可改**。环断在代码和图之间。

---

## 二、把触发规则放进图

做法：触发规则也是一种 `kind='rule'` 的节点，用 `trigger|` 前缀区分。

```
rule|触发·放宽
  body：触发·放宽：when=多记、多留、放宽、调高、加大；op=thr↑；key=auto
          ↓ yields（触发词本身就是元素）
        元素「多记」「多留」「放宽」「调高」「加大」
```

于是命中**走元素**，不查代码：

```
文本「我想多记几条」
  → 元素「多记」在图里
  → 元素「多记」被 rule|触发·放宽 yields
  → 命中 rule|触发·放宽 → 执行 thr↑
```

好处不只是"好看"：

- 触发规则有**版本链**（能被改、能回退）
- 有**极性账本**（`+` 放宽 / `−` 收紧）
- 能被**带符号环检测**看见
- 能被**独立审计**检查

---

## 三、第 5 条：元触发

前 4 条触发规则改的是配置型规则（阈值、词表、措辞）。
第 5 条不同——**它改的是触发规则自己**：

```
rule|触发·改触发
  body：触发·改触发：when=改触发条件、去掉这个触发、改掉那条触发、这个触发条件、别再因为
                    op=stop+；key=when
        ↓ targets
  rule|触发·放宽 / 收紧 / 加停用 / 移停用
```

`op=stop+` 在这里的作用是：**把某个词从目标规则的 `when` 里删掉**，
也就是让那个触发条件失效。

### 实测

```
改前 触发·放宽 when：多记、多留、放宽、调高、加大

思考：去掉「放宽」这个触发条件吧
  → 元素「这个触发条件」（6 字，比「多记」锐，优先命中）
  → rule|触发·改触发
  → stop+ 作用于 rule|触发·放宽 的 when
  → 「多记」被删

改后 触发·放宽 when：多留、放宽、调高、加大

「多记」还能触发吗：不能了   ← 环合上了
「调高」还能触发吗：能        ← 只动了那一个词
```

**系统改掉了自己的触发条件。**

## 四、为此要动的两处底层

### 4.1 `stop±` 要能改"某个键的值"

原本 `stop±` 只认词表型正文（一整列词那种）。触发规则的触发词藏在 kv 型的 `when` 里，
所以要扩展成：

```python
payload = {"key": "when", "w": "多记"}
```

顺带加一条保护：**不能把 `when` 删空**。删到最后一个词等于废掉这条规则，
那应该用 `supersedes` 明说，而不是偷偷 `stop+` 抹掉。

### 4.2 读生效版本，不读锚点

改了触发规则之后，锚点节点的正文还是旧的。如果读锚点，会出现：

> body 里已经没有「多记」了，match 却还认它。

**改完不生效，等于没改。** 所以 `all_triggers` 必须走 `current()` 拿生效版本。

## 五、完整闭环的形状

```
        ┌──────────────────────────────────────────┐
        │                                          │
   思考 ──mentions──> 元素                        │
                        │                         │
                        ↓ yields                  │
                 rule|触发·*（触发条件）           │
                        │                         │
                        │ enacts                  │
                        ↓                         │
                 rule|配置型规则（阈值/词表）      │
                        │                         │
                        ↓ 影响                    │
                   下一次思考 ────────────────────┘
```

四类节点（记忆、元素、规则、思考）+ 两类规则（配置型、触发型），
全部通过元素相连，触发条件也在环里。

## 六、自指深度的判据

闭环不等于"无限自指"。深度是可以量的，记作 $\delta^*$：
**同一对象被连续改写了多少次**。

| 层 | 判据 | 例子 |
|---|---|---|
| L1 | 带符号环极性 = −1 | 改了一次又改回来 |
| L2 | 带符号环极性 = +1 | 绕了两圈 |
| L3 | $\delta^*\ge2$ 且有 `closes` 边 | 参数改了又改回去，结构上多出一圈 |
| L4 | $\delta^*\ge3$ | 同一条规则被三次连续改写 |

**怎么量**：

```bash
python -m huanzao.cli c2 depth      # 打印 δ* 与层级
python -m huanzao.cli rule cycles   # 带符号环
python -m huanzao.cli rule audit    # 独立一致性检查
```

### 一个诚实的提醒

$\delta^*$ **能被造出来**——你连着跑三次改写，它就变 3。

所以它不是一个"能力分数"，而是一个**状态读数**。
不要为了让它变大而去跑它；那和"为了减肥去称体重"一样。

## 七、边界在哪

L5（语义自证、一致性自证）**不可达**，且这不是工程问题。

自指的闭合条件逼出边界算子只能是 $-I$：

$$U(2\pi)=F_0\ \wedge\ U(4\pi)=I\ \Longrightarrow\ F_0=-I$$

$-I$ 是标量，不携带结构。于是系统能自证**"我走完了"**，
不能自证**"我走对了"**。后者必须外包给外部证据——人，或者另一个不经 `Φ_R` 的检查器。

这不是谦虚，是可证的边界。详见 [04-自指与人格](04-自指与人格.md)。
